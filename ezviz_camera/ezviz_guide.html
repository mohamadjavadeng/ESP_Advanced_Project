EZVIZ H8c + Python

Live stream, PTZ control, human detection — study guide. Camera IP 192.168.100.29.

TL;DR — what works how
GoalMethodWhereStatus
Live videoRTSP + OpenCVLocal network Works locally
Pan / TiltEZVIZ cloud API (pyezvizapi) Internet + account Cloud only
Human detection dataEZVIZ cloud API / MQTT push Internet + account Cloud only

Key point: video is local (RTSP), but PTZ and AI detection are not exposed locally — they ride on your EZVIZ account in the cloud.

0. Setup

pip install opencv-python      # already installed: 4.13.0
pip install pyezvizapi          # for PTZ + detection (cloud)

Enable RTSP first in the EZVIZ phone app:
Device Settings → your camera → … → Local Service / LAN Live View → RTSP on, and note the verification code (6 uppercase chars on the camera label).

1. Live stream (RTSP + OpenCV)

Script: stream.py

RTSP URL format

rtsp://admin:<CODE>@192.168.100.29:554/H264/ch1/main/av_stream   # HD
rtsp://admin:<CODE>@192.168.100.29:554/H264/ch1/sub/av_stream    # SD (smoother)
  • Username is always admin.
  • Password = the verification code (NOT your account password).
  • Port 554. Some firmwares also accept /Streaming/Channels/101 (main) and /102 (sub).

Run it

# PowerShell — set code once
$env:EZVIZ_CODE="ABCDEF"
python stream.py            # main stream
python stream.py --sub      # low-res, smoother over WiFi

Keys in the window: q quit, s save snapshot.

The script sets OPENCV_FFMPEG_CAPTURE_OPTIONS=rtsp_transport;tcp. TCP is much more reliable than UDP over WiFi and stops the torn / grey frames.

Core of the code

import os, cv2
os.environ["OPENCV_FFMPEG_CAPTURE_OPTIONS"] = "rtsp_transport;tcp"

url = "rtsp://admin:CODE@192.168.100.29:554/H264/ch1/main/av_stream"
cap = cv2.VideoCapture(url, cv2.CAP_FFMPEG)
while True:
    ok, frame = cap.read()
    if not ok: continue
    cv2.imshow("EZVIZ H8c", frame)
    if cv2.waitKey(1) & 0xFF == ord("q"): break

2. Pan / Tilt control

Script: ptz_and_detection.py

Is it possible from Python? Yes — but via the cloud, not the LAN. The H8c does not expose PTZ over local RTSP/ONVIF reliably. The community library pyezvizapi logs into your EZVIZ account and sends PTZ commands through EZVIZ servers.

# PowerShell
$env:EZVIZ_USER="you@email.com"
$env:EZVIZ_PASS="account_password"
$env:EZVIZ_SERIAL="BB1234567"      # serial on the label / in app

python ptz_and_detection.py move up 5
python ptz_and_detection.py move left 3

Real API in pyezvizapi 1.0.x (installed) — move = START then STOP:

import time
from pyezvizapi.client import EzvizClient
client = EzvizClient(user, password, "eu")     # region: eu / us
client.login()

# ptz_control(command, serial, action, speed=5)
#   command = "UP"|"DOWN"|"LEFT"|"RIGHT"   action = "START"|"STOP"
client.ptz_control("UP", serial, "START", 5)
time.sleep(0.6)                                 # nudge duration
client.ptz_control("UP", serial, "STOP", 5)

# absolute coordinate move (0..1):
client.ptz_control_coordinates(serial, 0.4, 0.6)
No official API docs exist — pyezvizapi is reverse-engineered. Method names change between versions. To list what your install offers: python -c "from pyezvizapi.client import EzvizClient; print([m for m in dir(EzvizClient) if not m.startswith('_')])" — see the GitHub repo.

3. Human detection data

Possible? Partly — via the cloud account, not the local stream.

  • The camera runs AI human detection on-device, but the events are pushed to the EZVIZ cloud, not served on the LAN.
  • pyezvizapi can read status/alarm fields such as Motion_Trigger, PIR/alarm-notify flags, and pull recent alarm snapshots; real-time events arrive via the app's MQTT push channel.
  • Field names differ by model/firmware — dump everything first:
python ptz_and_detection.py status   # prints full device info + detection fields
Want fully-local human detection instead? Run detection yourself on the RTSP frames you already get in stream.py — feed each frame to a model (OpenCV HOG, YOLO/Ultralytics, or MediaPipe). That needs no cloud and no account, and you fully control the data. Good follow-up if the cloud route is too limited.

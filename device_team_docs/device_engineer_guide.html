For the excavator device engineer · How your Raspberry-Pi controller feeds the GeoMind cloud, the fleet dashboards and the new web app — and exactly what we need from you for the live test.

1 · The big picture

Your device is already the first real machine (EXC-01) in a live fleet-monitoring system. Everything you write to GeoMind flows automatically into two dashboard surfaces: the GeoMind portal dashboards and a new standalone web app. Your firmware needs no functional changes — it already speaks the right contract.

Your side (device)GeoMind cloud (shared account)Our side (bridge + web app)

2 · Nothing changes in your data contract

Keep writing exactly what you write today. The system consumes your three resources as-is:

  • excavator1_status (vector layer #66534, one Point feature): current_depth, target_depth, driver, rfid_uid, driver_present, over_dig_alarm, sensor_alarm, hse_alarm, last_alarm_picture, updated_at — updated by your CloudSync every ~5 s. Keep reading target_depth back before writing (operators edit it in the portal; that loop is used in demos).
  • excavator1_log (table): change-only rows with your event enum init | over_dig_on/off | sensor_alarm_on/off | hse_on/off | driver_change.
  • excavator1_sessions (table): one row per RFID driver session with alarm counters.
  • HSE photos: keep uploading alarm_YYYYMMDD_HHMMSS.jpg and attaching to the status feature — they now appear automatically in the web app's EXC-01 gallery (newest six, "DEVICE UPLOAD" badge) and in map popups.

3 · What we need from you (3 items)

1

Switch device auth from password to the API key

The account allows one password session at a time. Every time your device logs in with username/password it kicks whoever is using the GeoMind portal (and vice-versa — a human login can kill your device's session mid-run: Session has been revoked). An API key is session-less and immune.

A key named pdo_device_service is already created for you. Its value is NOT in this document — ask Hamed for it and keep it out of git.

# monitoring_control.py — replace the password client with:
client = GeoboxClient(host="https://app.geo-mind.ai",
                      apikey=DEVICE_APIKEY,      # from env, not hardcoded
                      verify=False)
# raw requests (photo upload/download etc.): append ?apikey=<key>
# your geobox_token.py already supports apikey mode — same pattern.

Everything else (feature.save, create_row, upload_file, create_attachment) works unchanged with the apikey client — verified on this tenant.

2

Keep resource names excavator1_*

The bridge and dashboards find your data by these names. If you provision fresh (your monitoring_state.json lost), let your code re-create the same names — UUIDs may change, names must not.

3

Agree a test window with Hamed

During the test we run the bridge on our side (live_sim.py --bridge-only — mirrors ONLY your real device into the fleet, no simulated machines polluting your data). Outside agreed windows the full simulator may be running, which also bridges you but adds 17 fake machines around you.

6 · Troubleshooting

SymptomCause / fix
AuthenticationError: Session has been revoked on the deviceYou're still on password auth and someone logged into the portal. Switch to the API key (§3.1).
Portal shows "Session Terminated" for Hamed while device runsSame root cause, other direction. API key fixes both.
updated_at fresh but web app EXC-01 staleBridge not running. Ask Hamed to start it (it's our side).
Photo uploaded but not in the galleryGallery shows the newest 6 attachments of the status feature; check the attachment succeeded (create_attachment return) and the filename starts with alarm_.
Map dot doesn't move though popup data is freshNormal: dots come from a tile cache reseeded each bridge tick (~10 s extra). Popups/tables are authoritative.
Feature write fails with KeyError: 'geometry'The SDK's feature.update requires geometry — send the full Feature payload with srid=4326 (your CloudSync already does).

7 · Reference — quick endpoints (all with ?apikey=)

Feature read : GET  /v1/vectorLayers/<uuid>/features/?limit=5&out_srid=4326
Table rows   : GET  /v1/tables/<uuid>/rows/?skip=0&limit=100     (page/order_by can 500 — use skip/limit)
File download: GET  /v1/files/<uuid>/download/
Attachments  : GET  /v1/attachments/?resource_type=vector&resource_uuid=<layer>   (both params REQUIRED)

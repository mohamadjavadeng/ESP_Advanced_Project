GeoMind Device-Side Integration — Change Report

Excavator EXC-01 · Raspberry-Pi controller (monitoring_control.py) · what I read from / write to GeoMind, the two HSE-event concepts, and the exact code changes made. Angle-reading and HSE-alarm-reading were left untouched by design.

TL;DR — I mapped the full GeoMind read/write contract (vectors + tables), then aligned the cloud-sync code to it. The headline change the device team asked for is switching cloud auth from password to the session-less API key. I also hardened the feature write (correct map position on any Pi), made the event log atomic and single-token so the fleet bridge parses it, added a typed auth-reconnect, and fixed a latent Flask bind crash. The angle pipeline (ESP32 → depth) and the camera HSE-alarm pipeline were not modified. Two files changed: raspberry_pi/monitoring_control.py, raspberry_pi/geobox_token.py.

1 · GeoMind VECTORS — what I read vs write

A "vector" is a spatial layer (geometry + attribute properties). The device owns exactly one live vector; everything else on the pdo.excavator account is fleet/context data the bridge (their side) owns.

3 · The two HSE concepts (Event_type_table.png & hipo.png)

lsr_rule — Life-Saving Rule

Every AI event is tagged with the IOGP Life-Saving Rule it relates to, so the event log speaks PDO's HSE compliance language:

Event typeLSR
Person Detected, Utility Strike, OHL ClearanceLine of Fire
Over-dig, Dig Outside Permit, Zone BreachWork Authorisation
Person Under Suspended LoadSafe Mechanical Lifting
Vehicle Proximity, V2V Near-MissDriving
Device Fault— (not safety-relevant)

hipo — High-Potential incident flag

A 0/1 flag on each event: a near-miss whose realistic worst case was serious injury/fatality — the leading HSE indicator, feeding the Command-Center "Near-Misses Auto-Captured" KPI. Each captured HiPo carries GPS + depth + a camera frame as evidence.

Who writes them: DERIVED — not by the device Both lsr_rule and hipo live on the fleet event log and are assigned by the bridge/datagen.py (their side) from the event type + severity. The device's job is only to emit the correct single-token event string (e.g. hse_on, over_dig_on) so the bridge can map it to the right LSR and decide HiPo. This is exactly why change #4 below (atomic, single-token log rows) matters — a comma-joined "hse_on,driver_change" would not map to any rule.

4 · Code changes made

All edits are confined to the cloud-sync layer (CloudSync class, its connect(), the main() argument block, the import guard) and the geobox_token.py helper. Verified: no protected code changed (§5).

1. Auth: password → session-less API key device-team request #1

Password login evicts the human portal user and gets revoked when anyone else logs in. Switched to the API key, which is session-less. Key comes from the environment (never git/logs); password remains a last-resort fallback with a loud warning.

# CloudSync.connect() — before
self.client = GeoboxClient(host=..., username=user, password=pass, verify=...)
# after
if self.args.geomind_apikey:
    self.client = GeoboxClient(host=..., apikey=self.args.geomind_apikey, verify=verify)
elif self.args.geomind_user and self.args.geomind_pass:
    print("[cloud] WARNING: no API key; password login evicts the portal user…")
    self.client = GeoboxClient(host=..., username=..., password=..., verify=verify)
else:
    raise RuntimeError("no GeoMind credentials: set --geomind-apikey / $GEOMIND_APIKEY")

New arg --geomind-apikey (default $GEOMIND_APIKEY / $PDO_DEVICE_APIKEY). The hardcoded password default was removed from argparse (now $GEOMIND_PASS) so the credential is no longer committed to git. The key rides as a ?apikey= query param, so TLS verification stays ON by default (pass --insecure only for a self-signed tenant cert).

2. Robust feature write — correct map position on any Pi

The old read used get_feature(..., out_srid=4326), which makes the SDK call feature.transform() — that needs the geobox[geometry] extra (shapely + pyproj) and raises on a still-empty geometry, so it can crash the poll loop on a stock Pi. The write used feature.save(), whose CRS tag is fragile. Switched to the contract's documented pattern:

# poll_and_push()
feature = self.layer.get_feature(self.feature_id)          # no out_srid -> no transform()
props   = dict(feature.data.get("properties") or {})
…
feature.update({"type": "Feature",
                "geometry": {"type": "Point", "coordinates": [lon, lat]},  # WGS84
                "properties": props}, srid=4326)           # -> ?in_srid=4326, server reprojects

Verified against the installed SDK source: update() forces ?in_srid=4326 and requires a geometry key (else KeyError). This removes the shapely/pyproj dependency and guarantees the marker lands at the real lat/lon instead of being read as metres.

3. Atomic, single-token event log

When several states flip in one cycle the old code wrote a comma-joined event ("hse_on,driver_change") the bridge can't parse. Now each transition writes one row per token, and the log cursor advances only past rows that actually landed — so a transient cloud error on one token leaves that edge live for retry (no lost edge, no duplicate). This was rewritten and a regression it introduced was caught in adversarial review and fixed (see §6).

# each token flips exactly one state component; stop at first failure
steps = self._event_steps(key, first)   # [(token, component_idx, new_value), …]
for token, idx, newval in steps:
    try:
        self.table.create_row(…, event=token); advanced[idx] = newval
    except Exception: break               # remaining edge retried next cycle
self.last_logged = tuple(advanced)

4. Typed auth-loss reconnect

The steady-state loop now catches geobox.exception.AuthenticationError by type and re-authenticates + re-resolves objects (defence-in-depth; the API-key path should never hit it). The import is guarded with a sentinel so an older SDK without that class can't disable cloud sync.

5. Flask bind-host crash fix (from raspberry_pi/bind_error_fix.txt)

ap.add_argument("--http-host", default="192.168.100.43")   # crashes: EADDRNOTAVAIL when DHCP differs
ap.add_argument("--http-host", default="0.0.0.0")          # always binds; ESP32s still POST to the real IP

A hardcoded IP that the Pi doesn't currently own makes the whole server die on bind. 0.0.0.0 is the documented permanent fix and matches the HSE socket server. Relevant to the ESP32 location issue too — if the receiver can't bind, neither angle nor GPS POSTs land.

6. geobox_token.py helper fixes

  • Default username was PDO@excavator1 — that is the password, not the username (the username is pdo.excavator). A bare run therefore burned a failed login (lockout risk). Fixed the default and made API-key the preferred path (env-driven).
  • Added a pre-network guard: with neither key nor password set, it now exits with a clear message without contacting the server (no credential-less login attempt).

6 · How it was verified

  • Pre-edit verification (3 parallel agents): confirmed the SDK's save() vs update() semantics from source, the apikey/AuthenticationError API, and mapped the exact protected line-ranges before any edit.
  • Adversarial review (4 independent lenses): protected-integrity clean, auth, SDK-write, event-logic. It caught a real regression in change #3 (non-atomic edge advance could permanently drop a failed event token). Fixed and re-verified.
  • Unit test of the fix: a standalone replica of the log logic exercises the exact partial-failure scenarios (two edges in one cycle, second row fails) — 17/17 assertions pass: failed edge is retried, no duplicate row, cursor advances only past landed rows.
  • Syntax: both files python -m py_compile clean; no dangling references after the rename.

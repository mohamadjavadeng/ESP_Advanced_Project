2 · Your write contract (do not break)

2.1 excavator1_status — the live feature (layer #66534, ONE Point feature)

PropertyTypeMeaning / rule
current_depthFloat (m)bucket-tip depth = L1·sin(boom)+L2·sin(stick)
target_depthFloat (m)READ BACK from the feature before each write — operators edit it in the portal; it is the permitted depth that drives your over-dig alarm and our gauges
driver / rfid_uid / driver_presentStr / Str / Int 0-1from the RFID reader; unknown UID → "Unknown Driver", present=0
over_dig_alarm · sensor_alarm · hse_alarmInt 0/1your latched flags (over-dig hysteresis 0.05 m; sensor = stale>1.5 s or mpu fail; hse = camera person-in-zone dwell ≥3 s, 30 s link fail-safe)
last_alarm_pictureStrfilename of newest uploaded HSE photo
updated_atStr ISO-8601 UTCstamp every write — dashboards use it as your heartbeat
# update pattern (SDK requires geometry on Feature.update — send full payload, srid=4326)
layer = client.get_vector_by_name("excavator1_status")   # resolve by NAME (uuids can rotate)
feat  = layer.get_features(geojson=False, limit=3)[0]
props = dict(feat.properties); props.update(new_values); props["updated_at"] = iso_now()
tgt   = props.get("target_depth")            # ← the read-back loop
feat.update({"type": "Feature",
             "geometry": {"type": "Point", "coordinates": [lon, lat]},   # WGS84
             "properties": props}, srid=4326)

2.2 excavator1_log — change-only history rows

Columns: ts, driver, depth, target_depth, over_dig_alarm, sensor_alarm, hse_alarm, lat, lon, event. Write ONLY on state change (plus init at startup). Event enum (the bridge and dashboards parse these exact strings):

init · heartbeat · over_dig_on/over_dig_off · sensor_alarm_on/sensor_alarm_off · hse_on/hse_off · driver_change

table = client.get_table_by_name("excavator1_log")

3 · What happens downstream (read-side contracts you must not break)

  • Bridge (live_sim.py, ours): every 20 s copies your status feature into pdo_fleet WHERE mid='EXC-01' (field mapping: current_depth→depth_m, target_depth→target_depth_m, + derived boom/stick angles and status), and copies NEW excavator1_log/_sessions rows (row-id cursor) into pdo_fleet_log/pdo_sessions with mid='EXC-01'. Renaming your columns/events breaks this mapping.
  • Saved queries (pdo_q2_*) power every dashboard table/gauge; several take a machine param m. Executed via POST /v1/queries/exec/ (the SDK's Query.execute() cannot override params).
  • Map tiles are cache-only on this account (live tile renderer 500s). Feature writes are invisible on MAPS until a cache reseed — the bridge reseeds each tick: 
    POST /v1/vectorLayers/<uuid>/cache/seed/?apikey=…
{"from_zoom": 0, "to_zoom": 14, "ignore_cache": true, "workers": 2, "user_id": 12455}
    JSON/table reads are always fresh; only rendered dots lag.

4 · Adding MORE real devices later (EXC-02…)

Two options, in order of preference:

  1. Same pattern, new names: provision excavator2_status/_log/_sessions exactly like device 1 and tell Hamed — the bridge gains a second cursor block (5-line change on our side). Your firmware stays identical apart from --device-id excavator2.
  2. Direct-to-fleet (skips the bridge): update the pdo_fleet feature WHERE mid='EXC-02' + append pdo_fleet_log/pdo_sessions rows with a mid column. Schemas: fleet = your status fields renamed (depth_m, target_depth_m) + identity fields; log = your log + mid. Resolve layer uuids by NAME at startup (get_vector_by_name("pdo_fleet")) — uuids rotate when we re-provision. Coordinate with Hamed before writing to fleet resources.

5 · Platform gotchas (will bite you; all verified on this tenant)

GotchaRule
Single password sessionAPI key for anything long-running. Catch AuthenticationError by TYPE and reconnect if you must use passwords.
Feature.update KeyError 'geometry'Always send full Feature payload with geometry, srid=4326 (lon/lat).
get_features(geojson=True)Ignores limit, silently truncates at 100 rows. Use geojson=False, limit=10000, skip_geometry=True.
Geometry CRSStored EPSG:3857; write with srid=4326; reads return metres — use lat/lon PROPERTIES for positions.
Polygon / Polyline layersFeatures must be MultiPolygon / MultiLineString (plain Polygon/LineString rejected). Points are plain Point.
SQL identifiersfalse/true inside a column name breaks the parser (we renamed false_positive→is_false_alarm); no quoted identifiers.
List endpointsGET /v1/vectorLayers/ and /v1/files/ cap at ~10 items and ignore paging — always resolve by name/uuid, never trust lists.
Attachments list/v1/attachments/ REQUIRES resource_type + resource_uuid query params (else a 422 that looks like an empty list).
Table rows read/v1/tables/<uuid>/rows/?skip=0&limit=N — the page/order_by params can 500.
String field widthsDefault String width is short — long values need the field created with data={"width": N}.
